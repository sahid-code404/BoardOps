 17696→# BOARDOPS - PART 17
 17697→## DESIGN SYSTEM AND UI REQUIREMENTS
 17698→The visual design of BoardOps is a premium liquid-glass aesthetic inspired by Apple's design language, Linear, Notion, Stripe Dashboard, and Vercel. The core visual elements include frosted glass panels with backdrop blur effects, semi-transparent layered surfaces with subtle gradients, generously rounded corners ranging from 12px to 32px depending on component size, soft ambient shadows with multiple layers for depth, glassmorphic cards that appear to float above the background, and a refined color palette with both dark and light mode support. The background features subtle animated gradient meshes and mesh gradients that shift slowly to create a living, breathing interface. Every interactive element must have smooth hover states, press states, focus states, and transition animations. Page transitions must use Framer Motion with staggered children animations so elements appear sequentially rather than all at once. Cards should have a subtle scale and glow effect on hover. Buttons should have a ripple or glow effect on click. Toggles should animate smoothly between states. Tables should have row hover highlights and staggered entry animations. Forms should have floating labels, smooth focus transitions, and inline validation feedback. Loading states should use skeleton loaders with shimmer effects rather than spinners. Empty states should have beautiful illustrations or icons with helpful text. Error states should have clear messaging with recovery actions. Toast notifications should slide in from the top with glassmorphic styling. The dashboard should feature animated counters that count up when they come into view. Charts should animate their paths and bars on mount. The navigation should have an animated active indicator that slides between menu items. The entire interface must be responsive across mobile phones, tablets, and desktops with layouts that gracefully adapt. Accessibility must follow WCAG 2.1 AA standards with proper ARIA labels, keyboard navigation, screen reader support, and color contrast ratios.
 17699→
 17700→The frontend is built as a single-page application using React 19 with Vite as the build tool. The project structure follows a feature-based organization where each feature module contains its own components, hooks, services, types, and utilities. The top-level directories include app for app-level configuration, pages for route components, components for shared UI components, features for feature-specific modules, hooks for custom hooks, services for API clients, stores for Zustand stores, providers for context providers, types for TypeScript types, constants for application constants, utils for utility functions, assets for static assets, and styles for global styles. The routing is handled by React Router v7 with protected routes that check authentication and role before rendering. The layout system includes an auth layout for login and registration pages, a user layout for the user dashboard with a bottom navigation bar on mobile and a sidebar on desktop, and an admin layout for the admin panel with a sidebar navigation. The state management uses Zustand for client-side state such as current user, theme, and UI state, and TanStack Query for server-side state including all API data with automatic caching, refetching, and optimistic updates. The design system is implemented using Tailwind CSS v4 with custom design tokens for colors, spacing, typography, shadows, border radius, and animation durations. The liquid-glass effect is achieved through a combination of backdrop-blur, semi-transparent backgrounds, border gradients, and layered box shadows. ShadCN UI components are customized to match the glassmorphic design language. Framer Motion is used for page transitions, card animations, staggered list animations, toggle animations, and micro-interactions. The application is configured as a progressive web app with a service worker for offline caching, a web manifest for installation, and push notification readiness.
 17701→Design and build a world-class, production-ready SaaS web application with a premium mobile-first experience that feels comparable to Apple, Linear, Stripe Dashboard, Arc Browser, Vercel, Notion, Raycast, and iOS. The application must not look like a typical admin dashboard or Bootstrap website. Every screen should feel handcrafted, elegant, modern, immersive, and enterprise-grade. The interface should immediately communicate premium quality and attention to detail.
 17702→
 17703→Use a Mobile-First design philosophy. Every screen, interaction, navigation flow, animation, and component must be designed for smartphones first and then progressively enhanced for tablets, laptops, and large desktop displays. The mobile experience is the primary experience, not a simplified version of the desktop interface. Desktop layouts should expand naturally while maintaining the same visual language and interaction patterns.
 17704→
 17705→The entire UI must follow a premium Liquid Glass design language inspired by Apple's latest Human Interface Guidelines. Use translucent glass panels with backdrop blur, layered transparent surfaces, soft frosted glass effects, subtle reflections, dynamic light diffusion, elegant transparency, floating cards, ambient shadows, depth-based elevation, and smooth layered interfaces. Avoid heavy opaque backgrounds. Components should appear as floating glass objects above an animated background.
 17706→
 17707→Every component must have generously rounded corners. Cards should use border radii between 20px and 32px. Buttons should use 16px–24px radius depending on size. Input fields should use 18px radius. Modal windows should use 28px radius. Bottom sheets should use 32px radius. Drawers should have extra-soft rounded edges. Avoid sharp corners entirely.
 17708→
 17709→Create a premium glassmorphism system using semi-transparent surfaces with backdrop blur between 20px and 40px, subtle gradient overlays, soft white borders with low opacity, layered transparency, multiple shadow levels, and dynamic highlights. Every glass component should feel physically realistic without sacrificing readability.
 17710→
 17711→The application must support both Dark Mode and Light Mode from day one. Both themes should be individually designed instead of simply inverting colors. Dark mode should use deep charcoal, graphite, navy, and rich blacks with colorful glow accents. Light mode should use soft whites, neutral grays, subtle gradients, and elegant shadows. Theme switching should animate smoothly without flashing.
 17712→
 17713→The background should never be static. Create a living background using animated mesh gradients, slowly moving gradient blobs, soft radial glows, animated light rays, floating particles, subtle noise textures, and depth layers. Animations should be extremely subtle and never distract from content.
 17714→
 17715→The application should feel alive. Every interaction must be fully animated using Framer Motion. Use spring-based animations with realistic physics instead of linear timing. Animate page transitions, route changes, cards, buttons, forms, menus, navigation, dialogs, notifications, lists, tables, charts, and widgets. Components should fade, slide, scale, blur, and stagger naturally. Nothing should appear instantly.
 17716→
 17717→Every page transition should include smooth shared layout animations, fade-through transitions, staggered child animations, and preserved scroll position. Navigation should feel comparable to native iOS applications.
 17718→
 17719→Buttons should feel tactile. Hover states should slightly lift the button with soft shadow expansion. Press states should slightly scale down with realistic spring animation. Primary buttons should emit subtle glow effects. Ghost buttons should animate border opacity and glass intensity. Icon buttons should smoothly morph between states.
 17720→
 17721→Cards should have hover elevation, soft scale effects, animated borders, dynamic highlights, and subtle floating motion. KPI cards should animate numbers counting upward when entering the viewport. Widgets should animate independently as they load.
 17722→
 17723→Every icon should use a consistent modern icon system such as Lucide React or Phosphor Icons. Icons should animate on hover and interaction.
 17724→
 17725→Typography should use a premium modern font stack such as SF Pro Display, Inter, Geist, or IBM Plex Sans. Maintain a clear visual hierarchy with generous spacing, balanced line heights, consistent typography scales, and perfect alignment. Text should never feel cramped.
 17726→
 17727→Forms must feel premium. Use floating labels, animated placeholders, inline validation, success indicators, animated error messages, password visibility toggles, input icons, keyboard-friendly navigation, auto-focus transitions, and intelligent spacing. Validation should occur in real time without interrupting typing.
 17728→
 17729→Tables should be completely redesigned from traditional enterprise tables. Use glass containers, sticky headers, animated sorting, expandable rows, smooth pagination, responsive card mode on mobile, lazy loading, virtualization for large datasets, row hover effects, contextual actions, and elegant filtering.
 17730→
 17731→Navigation must be adaptive. On mobile use a premium bottom navigation bar combined with contextual floating action buttons and bottom sheets. On tablets use collapsible side navigation. On desktop use a beautiful glass sidebar with animated indicators, nested navigation, collapsible groups, smooth icon animations, and searchable navigation.
 17732→
 17733→Dashboard widgets should be modular, draggable (desktop), configurable, responsive, and animated. Charts should use smooth SVG animations with animated paths, gradients, tooltips, hover interactions, legends, and live updates.
 17734→
 17735→Loading experiences should never use traditional spinners. Use shimmer skeleton loaders, progressive loading, optimistic UI updates, animated placeholders, and staged content loading.
 17736→
 17737→Empty states should include premium illustrations, subtle animations, friendly messaging, contextual actions, and onboarding hints.
 17738→
 17739→Error states should include clear explanations, recovery actions, retry buttons, diagnostics when appropriate, and polished visual design.
 17740→
 17741→Notifications should use elegant glass toast components with icons, progress indicators, stacking behavior, smooth entrance and exit animations, swipe-to-dismiss on mobile, and intelligent grouping.
 17742→
 17743→Dialogs should use glassmorphic modals with blurred backgrounds, spring animations, keyboard accessibility, focus trapping, and smooth dismissal.
 17744→
 17745→Use bottom sheets extensively on mobile instead of modal dialogs whenever appropriate. Sheets should support drag gestures, snapping positions, smooth physics, and gesture-based dismissal.
 17746→
 17747→Scrolling should feel luxurious. Use momentum scrolling, smooth anchor navigation, sticky headers, floating controls, parallax effects where appropriate, and elegant section transitions.
 17748→
 17749→Micro-interactions should exist everywhere. Switches should animate fluidly. Toggles should morph naturally. Progress bars should animate smoothly. Checkboxes should draw their checkmark. Radio buttons should ripple. Dropdowns should expand with spring animations. Chips should animate selection. Tabs should smoothly slide an active indicator.
 17750→
 17751→Accessibility is mandatory. Follow WCAG 2.1 AA guidelines. Support keyboard navigation, focus management, ARIA attributes, reduced motion preferences, screen readers, sufficient contrast ratios, semantic HTML, and proper touch targets.
 17752→
 17753→Performance is equally important. Use React with TypeScript, Vite or Next.js, Tailwind CSS, Framer Motion, React Query, React Hook Form, Zod validation, lazy loading, route-based code splitting, virtualization, image optimization, memoization, optimized animations, and GPU-accelerated transforms. Maintain 60 FPS animations across modern devices.
 17754→
 17755→Design every component as reusable, composable, theme-aware, accessible, and production-ready. Build a complete design system including typography, spacing, colors, elevations, glass styles, shadows, radii, icons, buttons, inputs, cards, tables, charts, navigation, modals, bottom sheets, toasts, loaders, badges, avatars, dropdowns, tabs, calendars, timelines, accordions, tooltips, progress indicators, data visualization components, and responsive layouts.
 17756→
 17757→The final result should feel like a premium enterprise SaaS product that could compete with products from Apple, Stripe, Linear, Vercel, Notion, and modern fintech platforms. Every pixel should feel intentional, every animation should feel natural, and every interaction should feel polished. The application must be fully responsive, mobile-first, production-ready, visually stunning, highly performant, accessible, scalable, and suitable for millions of users.The entire UI/UX must follow a Mobile-First, Adaptive-Responsive architecture rather than traditional responsive web design.
 17758→
 17759→The application should never simply shrink desktop components to fit smaller screens. Every breakpoint must have its own optimized layout, spacing, navigation pattern, interaction model, and information hierarchy.
 17760→
 17761→The UI must automatically adapt to every screen size while maintaining the same premium experience across mobile phones, foldable phones, tablets, laptops, desktops, ultrawide monitors, and future devices.
