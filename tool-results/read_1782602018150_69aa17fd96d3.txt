     1→ 17696→# BOARDOPS - PART 17
     2→ 17697→## DESIGN SYSTEM AND UI REQUIREMENTS
     3→ 17698→The visual design of BoardOps is a premium liquid-glass aesthetic inspired by Apple's design language, Linear, Notion, Stripe Dashboard, and Vercel. The core visual elements include frosted glass panels with backdrop blur effects, semi-transparent layered surfaces with subtle gradients, generously rounded corners ranging from 12px to 32px depending on component size, soft ambient shadows with multiple layers for depth, glassmorphic cards that appear to float above the background, and a refined color palette with both dark and light mode support. The background features subtle animated gradient meshes and mesh gradients that shift slowly to create a living, breathing interface. Every interactive element must have smooth hover states, press states, focus states, and transition animations. Page transitions must use Framer Motion with staggered children animations so elements appear sequentially rather than all at once. Cards should have a subtle scale and glow effect on hover. Buttons should have a ripple or glow effect on click. Toggles should animate smoothly between states. Tables should have row hover highlights and staggered entry animations. Forms should have floating labels, smooth focus transitions, and inline validation feedback. Loading states should use skeleton loaders with shimmer effects rather than spinners. Empty states should have beautiful illustrations or icons with helpful text. Error states should have clear messaging with recovery actions. Toast notifications should slide in from the top with glassmorphic styling. The dashboard should feature animated counters that count up when they come into view. Charts should animate their paths and bars on mount. The navigation should have an animated active indicator that slides between menu items. The entire interface must be responsive across mobile phones, tablets, and desktops with layouts that gracefully adapt. Accessibility must follow WCAG 2.1 AA standards with proper ARIA labels, keyboard navigation, screen reader support, and color contrast ratios.
     4→ 17699→
     5→ 17700→The frontend is built as a single-page application using React 19 with Vite as the build tool. The project structure follows a feature-based organization where each feature module contains its own components, hooks, services, types, and utilities. The top-level directories include app for app-level configuration, pages for route components, components for shared UI components, features for feature-specific modules, hooks for custom hooks, services for API clients, stores for Zustand stores, providers for context providers, types for TypeScript types, constants for application constants, utils for utility functions, assets for static assets, and styles for global styles. The routing is handled by React Router v7 with protected routes that check authentication and role before rendering. The layout system includes an auth layout for login and registration pages, a user layout for the user dashboard with a bottom navigation bar on mobile and a sidebar on desktop, and an admin layout for the admin panel with a sidebar navigation. The state management uses Zustand for client-side state such as current user, theme, and UI state, and TanStack Query for server-side state including all API data with automatic caching, refetching, and optimistic updates. The design system is implemented using Tailwind CSS v4 with custom design tokens for colors, spacing, typography, shadows, border radius, and animation durations. The liquid-glass effect is achieved through a combination of backdrop-blur, semi-transparent backgrounds, border gradients, and layered box shadows. ShadCN UI components are customized to match the glassmorphic design language. Framer Motion is used for page transitions, card animations, staggered list animations, toggle animations, and micro-interactions. The application is configured as a progressive web app with a service worker for offline caching, a web manifest for installation, and push notification readiness.
     6→ 17701→Design and build a world-class, production-ready SaaS web application with a premium mobile-first experience that feels comparable to Apple, Linear, Stripe Dashboard, Arc Browser, Vercel, Notion, Raycast, and iOS. The application must not look like a typical admin dashboard or Bootstrap website. Every screen should feel handcrafted, elegant, modern, immersive, and enterprise-grade. The interface should immediately communicate premium quality and attention to detail.
     7→ 17702→
     8→ 17703→Use a Mobile-First design philosophy. Every screen, interaction, navigation flow, animation, and component must be designed for smartphones first and then progressively enhanced for tablets, laptops, and large desktop displays. The mobile experience is the primary experience, not a simplified version of the desktop interface. Desktop layouts should expand naturally while maintaining the same visual language and interaction patterns.
     9→ 17704→
    10→ 17705→The entire UI must follow a premium Liquid Glass design language inspired by Apple's latest Human Interface Guidelines. Use translucent glass panels with backdrop blur, layered transparent surfaces, soft frosted glass effects, subtle reflections, dynamic light diffusion, elegant transparency, floating cards, ambient shadows, depth-based elevation, and smooth layered interfaces. Avoid heavy opaque backgrounds. Components should appear as floating glass objects above an animated background.
    11→ 17706→
    12→ 17707→Every component must have generously rounded corners. Cards should use border radii between 20px and 32px. Buttons should use 16px–24px radius depending on size. Input fields should use 18px radius. Modal windows should use 28px radius. Bottom sheets should use 32px radius. Drawers should have extra-soft rounded edges. Avoid sharp corners entirely.
    13→ 17708→
    14→ 17709→Create a premium glassmorphism system using semi-transparent surfaces with backdrop blur between 20px and 40px, subtle gradient overlays, soft white borders with low opacity, layered transparency, multiple shadow levels, and dynamic highlights. Every glass component should feel physically realistic without sacrificing readability.
    15→ 17710→
    16→ 17711→The application must support both Dark Mode and Light Mode from day one. Both themes should be individually designed instead of simply inverting colors. Dark mode should use deep charcoal, graphite, navy, and rich blacks with colorful glow accents. Light mode should use soft whites, neutral grays, subtle gradients, and elegant shadows. Theme switching should animate smoothly without flashing.
    17→ 17712→

Create a living background using animated mesh gradients, slowly moving gradient blobs, soft radial glows, animated light rays, floating particles, subtle noise textures, and depth layers. Animations should be extremely subtle and never distract from content.
    19→ 17714→
    20→ 17715→The application should feel alive. Every interaction must be fully animated using Framer Motion. Use spring-based animations with realistic physics instead of linear timing. Animate page transitions, route changes, cards, buttons, forms, menus, navigation, dialogs, notifications, lists, tables, charts, and widgets. Components should fade, slide, scale, blur, and stagger naturally. Nothing should appear instantly.
