💰 Funds Overview — Aggregation Formula
Total Deposit
Σ APPROVED Payments
−
Total Expenses
Σ Expenses (non-deleted)

Remaining Fund
Available Balance
Per-user deposit = Σ that user's APPROVED payments (month) · Per-user need-to-pay = bill dueAmount (period)
Refund credit = (Σ APPROVED) − (Σ billed, past periods) − (Σ already REFUNDED)
Bill → Payment Flow
① Admin generates bill → D1 Bills (status: GENERATED) + notify user → D5
② User views bill → submits payment → D2 Payments (status: PENDING) + notify admins
③ Admin approves → D2 (status: APPROVED) → recompute D1 paidAmount/due/status → notify user
④ If overpaid → admin processes refund → D2 (status: REFUNDED) → recompute D1 → notify user
Funds & Expense Flow
① Admin adds expense → D3 Expenses
② Funds dashboard reads D2 (APPROVED) for deposits + D3 for expenses
③ Remaining = Deposits − Expenses (real-time)
④ Per-user: deposit = Σ user's APPROVED payments · need-to-pay = D1 dueAmount
⑤ Refund Pending KPI = count of users with credit > 0
⚙️ Bill ↔ Payment Sync Rules (recomputeBillPaidState)
Every payment status change (approve, reject, void, delete, refund, restore) triggers a full recompute of the linked bill:
• paidAmount = Σ APPROVED payments − Σ REFUNDED payments (on that bill)
• dueAmount = max(0, totalAmount − paidAmount)
• status = PAID (if paid ≥ total) · PARTIALLY_PAID (if paid > 0) · GENERATED (if paid = 0)
• Idempotent: re-approving an approved payment is a no-op (no double-counting)
